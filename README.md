# Evenly iOS 功能文档

最后更新：2026-06-24

Evenly 是一款多人协作分账应用。用户可以创建共享账本、添加成员、记录支出、确认或否决账单，并查看实时分账结果与结算方案。

## 1. 产品目标

### 1.1 使用场景

适用于多人出行、聚餐、合租等共同消费场景。账本成员可以共同维护同一本账，系统基于支出记录计算每个人应收或应付的金额。

典型示例：

Alex、Sylvia、Stella、Tristen 一起旅行。Alex 垫付午饭 300 元，四人均分后，Sylvia、Stella、Tristen 各需向 Alex 支付 75 元。

### 1.2 核心原则

- 多人共享同一本账本。
- 支出记录明确付款人、参与人和金额。
- 结算结果由账单数据计算得出，不作为最终财务事实单独维护。
- 账单支持确认和否决，降低分账争议。

## 2. 当前 iOS 技术概览

- 平台：iOS / iPadOS
- UI：SwiftUI
- 状态管理：`@StateObject`、`@EnvironmentObject`、`@Published`
- 网络层：`APIClient` + async/await
- 鉴权：JWT token，使用 Keychain 保存
- 默认接口地址：
  - Debug：`http://localhost:8000`
  - Release：`https://evenly.ismyh.cn`
  - 可通过 `Info.plist` 的 `EVENLY_API_BASE_URL` 覆盖
- Bundle ID：`com.yhma.Evenly`
- Xcode scheme：`Evenly`

## 3. 功能模块

### 3.1 登录与注册

入口：未登录时显示 `LoginView`。

当前能力：

- 邮箱 + 密码登录。
- 登录按钮在邮箱或密码为空时禁用。
- 密码输入支持显示/隐藏。
- 登录失败时展示错误信息。
- 注册入口支持从登录页切换。
- 注册表单包含用户名、邮箱、验证码、密码、确认密码。
- 用户名需以英文开头，可包含英文、数字、下划线，至少 3 位。
- 邮箱格式校验。
- 密码至少 6 位，确认密码需一致。
- 邮箱验证码发送后才允许输入验证码并完成注册。

依赖接口：

- `POST /auth/login`
- `POST /auth/register`
- `POST /auth/send-verification`
- `GET /users/me`

### 3.2 主导航

登录后进入 `ContentView`，底部包含两个 Tab：

- 账本：账本列表、当前账本详情、账单、成员、结算。
- 设置：账户信息、主题、数据管理、关于。

账本页顶部支持：

- 左上角打开账本抽屉。
- 搜索当前账本内账单。
- 右上角菜单添加账单、管理成员。
- 非 Owner 用户可从菜单退出账本。

### 3.3 账本管理

当前能力：

- 无账本时展示空状态，并提供添加账本按钮。
- 新建账本时输入账本名称。
- 创建账本时可添加参与者。
- 可搜索注册用户并添加到账本。
- 未注册邮箱可添加为临时成员。
- 非邮箱输入会作为本地参与者添加。
- 本地去重校验，避免重复添加同名参与者或同一用户。
- 当前账本 ID 保存到 `UserDefaults`，下次登录后优先恢复。
- 支持删除账本。
- 非 Owner 支持退出账本。

依赖接口：

- `GET /ledgers`
- `POST /ledgers`
- `GET /ledgers/{id}`
- `DELETE /ledgers/{id}`
- `DELETE /ledgers/{id}/members/me`

### 3.4 成员管理

入口：账本页右上角菜单 -> 管理成员。

当前能力：

- 展示当前成员数量和成员列表。
- 支持按邮箱或名字搜索用户。
- 搜索到注册用户后可点击添加。
- 搜索不到用户时可添加为临时成员。
- 支持直接添加临时成员。
- 成员列表显示注册用户 / 本地成员状态。
- 支持删除成员。
- 支持头像 URL 展示，失败时使用首字母或默认头像。

依赖接口：

- `GET /users/search`
- `POST /ledgers/{ledgerId}/members`
- `DELETE /ledgers/{ledgerId}/members/{userId}`

### 3.5 支出管理

入口：账本页右上角菜单 -> 添加账单。

当前能力：

- 创建账单时输入名称、金额、付款人、参与人。
- 金额输入仅允许数字和一个小数点，最多保留两位小数。
- 付款人必须是已注册成员。
- 临时成员目前不支持参与账单分摊。
- 付款人会自动加入参与人，且不能被取消。
- 保存按钮在缺少名称、金额、付款人、参与人或金额不大于 0 时禁用。
- 账单列表显示标题、付款人、参与人数、金额和状态。
- 支持按账单标题或付款人搜索。
- 支持删除账单。

依赖接口：

- `GET /expenses/ledgers/{ledgerId}/expenses`
- `POST /expenses/ledgers/{ledgerId}/expenses`
- `DELETE /expenses/{expenseId}`

### 3.6 账单确认与否决

当前能力：

- 账单状态包含 `pending`、`confirmed`、`rejected`。
- 账单行展示待确认、已确认、已拒绝状态。
- 当前登录用户是账单参与人且尚未确认/否决时，显示拒绝和确认按钮。
- 用户完成操作后按钮消失，并显示“你已确认”或“你已拒绝”。
- 操作失败时展示错误弹窗。

依赖接口：

- `POST /expenses/{expenseId}/confirm`

注意：iOS 端的拒绝操作也调用确认接口，并在请求体中传入 `status: rejected`。

### 3.7 分账结果

当前能力：

- 在账本详情内展示每位参与者的实时净额。
- `net > 0` 显示应收。
- `net < 0` 显示应付。
- `net = 0` 显示已结清。
- 本地分账结果基于当前账本支出即时计算。

计算逻辑：

1. 每笔账单按参与人均分。
2. 付款人余额增加“付款金额 - 自己应承担金额”。
3. 其他参与人余额减少各自应承担金额。

### 3.8 结算方案与结算记录

当前能力：

- 从后端读取结算方案。
- 无需结算时显示“账目已结清”。
- 有结算方案时展示付款人、收款人和金额。
- 支持点击确认结算，提交后刷新结算方案和历史记录。
- 展示结算历史，包括转账双方、金额和结算时间。

依赖接口：

- `GET /ledgers/{ledgerId}/settlements`
- `POST /ledgers/{ledgerId}/settlements`
- `GET /ledgers/{ledgerId}/settlements/history`

### 3.9 设置

当前能力：

- 展示当前用户头像、显示名、用户名、邮箱。
- 修改密码。
- 切换主题：系统、浅色、深色。
- 进入数据管理。
- 退出登录。
- 展示版本、隐私政策、服务条款。

依赖接口：

- `PUT /users/me/password`

### 3.10 数据管理

入口：设置 -> 导出与清除。

当前能力：

- 导出所有账本为纯文本文件。
- 清除本地缓存，不删除云端数据。
- 展示本地账本数量、账单总数、参与者总数。

## 4. 权限与规则

### 4.1 角色

- Owner：账本创建者，可管理账本和成员。
- Member：普通成员，可查看和参与账本内支出。

### 4.2 当前 iOS 侧体现

- 非 Owner 可退出账本。
- 成员管理和删除操作入口已提供，最终权限由后端接口控制。
- 修改或删除他人支出、账本解散等规则需要结合后端返回验证。

## 5. 已知限制

- 当前已配置基础 XCTest / UI Test target，可通过 `xcodebuild test` 运行冒烟测试；业务级自动化覆盖仍需继续补充。
- Debug 默认连 `localhost:8000`，在真机或非本机后端环境下需要配置 `EVENLY_API_BASE_URL`。
- 注册验证码依赖邮件服务，自动化测试需要可控测试邮箱或 mock 后端。
- 临时成员可以加入账本，但不能作为账单付款人或参与账单分摊。
- 数据导出目前为纯文本，不是结构化 CSV/JSON。
- 设置页的隐私政策和服务条款仍指向占位 URL。
- Asset Catalog 缺少 `AccentColor`，构建会有资源警告但不阻塞运行。
