# Evenly iOS 体验与数据一致性修复设计

日期：2026-06-28

## 目标

修复登录、账本摘要、成员搜索与刷新、临时成员、账单创建、结算展示和头像更新中的 11 项问题，使 iOS 页面始终展示后端真实状态，并提供可理解的输入、加载和失败反馈。

本轮不包含注册流程测试、临时成员参与账单分摊、完整 MVVM 重构或新的结算算法。

## 已确认根因

1. 登录页仍使用 SF Symbol，没有使用新 App Icon。
2. 登录页使用两个独立布尔焦点，滚动发生在键盘布局稳定前，不能可靠地把当前输入框移到可见区域。
3. 登录页只有交互式拖动收起键盘，空白点击区域没有覆盖页面，提交时也未主动清除焦点。
4. `GET /ledgers` 不返回摘要计数，iOS 只为当前账本加载成员和账单，因此其他账本显示为 0。
5. 后端搜索已支持邮箱和昵称模糊匹配，但新建账本页面只在点击“添加”后发起一次查询，并只取首个结果。
6. 成员管理页面持有进入页面时传入的 `Ledger` 快照；`LedgerStore` 更新后，页面仍遍历旧成员数组。
7. 新建账本把本地参与者转换为 `Person` 时没有设置 `isTemporary`，后端因此跳过这些无 `user_id` 的成员。
8. iOS 新建账单没有提交后端必填的 `expense_date`，导致 422；客户端又丢弃响应详情，只显示笼统错误。
9. 分账明细同时展示余额结果和结算方案，信息重复。
10. 当前用户没有待结算项时，“我的结算”仍显示“已结清”占位区块。
11. `UserProfile.avatarImage` 固定返回 `nil`，设置页和账本侧栏永远使用占位头像；上传失败时客户端也无法显示后端具体原因。

## 方案概览

采用“后端提供列表摘要，iOS 使用单一状态源”的方案。

- 后端账本列表直接返回成员数和账单数，避免 iOS 为列表逐本加载详情。
- `LedgerStore` 是账本、成员和账单状态的唯一来源；子页面只保存账本 ID，不持有长期快照。
- 用户搜索采用可取消的防抖请求，并展示完整候选列表。
- API 错误保留后端 `detail`，页面可显示真实失败原因。
- 登录输入和头像展示封装成可测试、可复用的小组件。

## 后端接口调整

### 账本摘要

`GET /ledgers` 的每项增加：

- `member_count: int`：包含所有者、注册成员和临时成员。
- `expense_count: int`：该账本的账单总数。

计数使用聚合查询生成，不能通过逐账本查询形成 N+1 请求。现有字段保持兼容。

### 用户搜索

继续使用 `GET /users/search?q=<query>&limit=<limit>`。后端当前的邮箱和昵称包含匹配满足需求，不新增接口。iOS 默认请求最多 5 条结果。

### 头像上传日志

`POST /users/me/avatar` 增加结构化日志：

- 开始：用户 ID、文件类型、文件大小。
- 成功：用户 ID、生成的对象路径或公开 URL。
- 失败：用户 ID、异常类型和安全的错误摘要。

日志不得记录 JWT、COS 密钥或图片内容。COS 异常转换为稳定的 HTTP 错误响应。

## iOS 数据模型与状态

### Ledger 摘要

`LedgerResponse` 和 `Ledger` 增加 `memberCount`、`expenseCount`。列表页面始终显示摘要字段；加载详情后，成员和账单数组变化时同步更新摘要值。

创建账本、添加或删除成员、添加或删除账单后，`LedgerStore` 在同一次主线程状态更新中更新对应账本及其摘要，避免页面短暂显示旧计数。

### 实时账本引用

成员管理页面接收 `ledgerId`，通过 `LedgerStore.ledgers` 派生当前账本。添加、删除或刷新完成后，当前成员列表立即重绘。操作期间仅禁用正在处理的目标，不冻结整个页面。

### 临时成员

新建账本中的参与者状态明确区分：

- 注册用户：包含 `userId`，`isTemporary = false`。
- 临时成员：没有 `userId`，`isTemporary = true`，名称同时映射到 `nickname` 和 `temporaryName`。

保存成功后使用后端返回的 `LedgerWithMembers` 更新 `LedgerStore`，不使用提交前的本地账本覆盖服务器结果。

### 账单日期与错误

新建账单默认日期为当天，并以 `yyyy-MM-dd` 发送到 `expense_date`。金额分摊继续只允许注册成员，保持现有后端约束。

`APIError` 增加包含状态码和后端 `detail` 的服务器错误。页面优先展示该详情；没有详情时再使用通用网络提示。

## 页面交互

### 登录页

- 将新 App Icon 复制为普通图片资源供页面使用，避免依赖不能稳定按名称读取的 App Icon 集合。
- 使用单个枚举型 `FocusState` 管理邮箱和密码。
- 邮箱键盘显示“下一项”，提交后聚焦密码。
- 密码键盘显示“登录”，提交时清除焦点并登录。
- 焦点变化后等待一轮布局更新，再将输入框滚动到键盘上方。
- 点击页面空白、向下拖动或点击登录时收起键盘。

### 新建账本成员搜索

- 输入至少 2 个字符后等待约 300ms 发起搜索。
- 输入变化时取消旧请求，过期结果不能覆盖新结果。
- 输入框下方显示最多 5 个候选，包含头像、昵称和邮箱。
- 点击候选立即加入参与者并清空搜索。
- 已添加用户从候选中排除；重复选择显示轻量提示。
- 没有匹配结果时显示“将「输入内容」添加为临时成员”。
- 网络失败显示重试状态，不能把网络失败误判成“没有用户”。

### 成员管理

- 添加注册成员或临时成员成功后立即展示在“当前成员”中。
- 删除成员成功后立即移除并更新人数。
- 成功提示不替代数据刷新；只有 `LedgerStore` 更新完成后才显示成功。

### 结算

- 分账明细页面移除“分账结果”，仅保留后端结算方案。
- 当前用户存在待付款或待收款项时才显示“我的结算”区块。
- 没有待结算项时直接省略该区块，结算记录仍正常显示。

### 头像

- 新增统一远程头像组件，供设置页、账本侧栏和成员候选复用。
- 选择图片后立即显示本地预览，并覆盖上传进度。
- 图片居中裁剪为 512×512 JPEG 后上传，避免拉伸。
- 上传成功后使用响应中的新 `avatar_url` 更新 `AuthManager`。
- 远程加载失败时显示姓名首字母，不显示空白或永久加载状态。
- 上传失败时恢复原头像并展示后端具体原因。

## 错误与并发处理

- 所有可见状态更新在主线程执行。
- 搜索任务在输入变化或页面消失时取消。
- 保存、添加、删除和上传操作防止重复提交。
- 后端成功但后续刷新失败时保留成功的本地响应，并提示刷新失败，不回滚成旧快照。
- API 日志记录方法、路径、状态码和请求 ID，不输出 JWT 或完整响应中的敏感数据。

## 测试策略

### 后端测试

- 账本摘要正确统计注册成员、临时成员和账单。
- 非成员不能读取账本摘要。
- 用户搜索支持邮箱与昵称片段，结果排除当前用户并遵守 limit。
- 账单缺少日期返回可识别错误，合法日期创建成功。
- 头像未配置、类型错误、超限和存储失败返回稳定错误。

### iOS 单元测试

- `LedgerResponse` 摘要字段解码并映射到 `Ledger`。
- 详情与变更操作同步更新成员数和账单数。
- 临时成员编码包含 `is_temporary` 和 `temporary_name`。
- 账单请求始终包含当天或用户选择的 `yyyy-MM-dd` 日期。
- API 错误解析后端 `detail`。
- 搜索结果过滤已添加用户，并忽略已取消请求的旧结果。
- “我的结算”仅保留与当前用户有关且未结清的建议。
- 头像 URL 更新和失败回退状态正确。

### iOS UI 测试

- 登录页显示新图标，邮箱可进入密码，提交后键盘消失。
- 键盘出现时邮箱和密码输入框保持可见。
- 新建账本输入片段后出现候选，点选后加入；无结果时可添加临时成员。
- 创建后临时成员出现在账本详情。
- 添加成员后当前成员列表立即更新。
- 新建账单成功保存；失败时显示后端原因。
- 已结清时不显示“我的结算”，分账明细仅显示结算方案。
- 更换头像后设置页与账本侧栏显示同一张新头像。

### 全量验证

1. 运行后端 pytest 全量测试。
2. 运行 iOS `EvenlyTests`。
3. 运行 iOS `EvenlyUITests`，使用隔离测试数据或启动参数。
4. 使用 iOS Simulator 完成 Debug 构建。
5. 使用提供的测试账号手工回归 11 项流程，并记录通过、失败和阻塞项。

## 验收标准

- 11 项问题均能按上述交互稳定复现为已修复状态。
- 页面不依赖重新打开才能看到成员、头像或摘要更新。
- 列表计数不依赖当前选中的账本。
- 失败信息能够区分输入、权限、网络和服务器错误。
- 后端与 iOS 自动化测试通过，模拟器构建成功。
